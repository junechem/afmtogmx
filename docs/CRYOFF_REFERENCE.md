# CRYOFF .off / .ff Reference

Distilled from `CRYOFF_manual_v14.6.4.pdf` (Wang group, Univ. of Arkansas; current
fortran source `cry4.1.f90`, updated 2023-06-11). This file is the authoritative
naming and units reference for **what comes out of CRYOFF**, which the `afmtogmx`
package consumes. When the package's internal naming disagrees with the manual,
the manual wins for *describing the physics*; the package's internal keys are
implementation detail.

Future AI sessions should treat this document as the source of truth for:
- What each interaction-type symbol means (e.g. `STR`, `POW`, `EXP`).
- The parameter order each symbol expects.
- Units of distance / energy / angle.
- Known naming inconsistencies inside `afmtogmx` (e.g. `CDI` vs `CDIH`).

## 1. File types

| Extension | Role | Generated by | Consumed by |
|-----------|------|--------------|-------------|
| `.ff`     | Fit protocol (cards, atom defs, interaction lists) | user | CRYOFF |
| `.ref`    | Reference forces / coordinates (per-conformation)  | AFM toolkit | CRYOFF |
| `.off`    | Fitted force-field output                          | CRYOFF | `afmtogmx`, post-processing |

The `.off` file itself contains five sections (`Atom Types:`, `Intra-Potential:`,
`Inter-Potential:`, `Molecular-Definition:`, `Table-Potential:`) — this is what
`afmtogmx.core.functions._find_off_keywords` splits on.

## 2. Card / keyword grammar

- Cards are `[CARDname]` — **case-insensitive**, only the capitalized prefix is
  significant (e.g. `[BONds]`, `[BON]`, `[bonds]` all parse identically).
- Comment chars: `;`  `#`  `!`  — rest of line ignored.
- Unknown keywords are silently ignored (no error).
- Card order is unconstrained unless otherwise stated.
- Recommended max line width: 80 chars.

## 3. Units

| Quantity | Intra-Potential / Inter-Potential | Molecular-Definition (GROMACS-style) |
|----------|------------------------------------|---------------------------------------|
| Energy   | kcal/mol                           | kJ/mol                                |
| Distance | Angstrom                           | nm                                    |
| Angle    | degree                             | degree                                |

The "Molecular-Definition" and "Table-Potential" sections of the `.off` file
have already been unit-converted for GROMACS. The "Intra-Potential" /
"Inter-Potential" sections are still in CRYOFF native units.

`afmtogmx.core.report` (the publication-ready exporter) prints from the parsed
*native-units* values (kcal/mol, Angstrom) — no conversion.

## 4. Molecular-definition cards (intramolecular)

All `[BON]/[ANG]/[BD3]/[DIH]/[CDIH]` blocks have the same row layout:

```
[Card] num
  type   N  fit_flag  P1 P2 ... PN
    int_atom1  int_atom2 [...]    <- N lines listing atom indices
```

`fit_flag` is `FIT` (optimize) or `FIX` (hold provided value).

### 4.1 [BONds] — 2-atom bonds (Table 1)

| Symbol | Meaning | Functional form | # params | Nonlinear params |
|--------|---------|-----------------|----------|------------------|
| `HAR`  | Harmonic | U = (P2/2)(r - P1)^2 | 2: (re, kb) | none |
| `QUA`  | Quartic  | U = (P2/2)(r-P1)^2 + (P3/3)(r-P1)^3 + (P4/4)(r-P1)^4 | 4 | none |

### 4.2 [ANGles] — 3-atom angles (Table 2). `int_atom2` is the center atom.

| Symbol | Meaning | Functional form | # params | Nonlinear params |
|--------|---------|-----------------|----------|------------------|
| `HAR`  | Harmonic | U = (P2/2)(theta - P1)^2 | 2: (theta_e, k0) | none |
| `QUA`  | Quartic  | quartic in (theta - P1)  | 4 | none |
| `RAH`  | Restrained-angle harmonic (quartic + harmonic restraint) | (quartic-form) + (P1/2)(theta - P2)^2 | 5+ | P2 (degree-as-rad caveat) |

`RAH` is a more elaborate form — restraint angle (P2) is in **degrees** for the
fixed/initial value but if marked nonlinear must be supplied in **radians**.
(See manual page 14 footnote.)

### 4.3 [BD3] — bonded 3-body cross terms (Table 3). `int_atom2` is center.

| Symbol | Meaning | # params | Nonlinear |
|--------|---------|----------|-----------|
| `QBB`  | Two identical quartic bonds with bond-bond cross term | 5 | none |
| `MUB`  | Modified Urey-Bradley (bond-angle cross term: P1*(r13-P1) * (r12 - P2 + r23 - P3)) | 4 (P1..P4) | P1, P2, P3 |

### 4.4 [DIHedrals] — 4-atom dihedrals (Table 4)

| Symbol | Meaning | Functional form | # params | Nonlinear |
|--------|---------|-----------------|----------|-----------|
| `HAR`  | Harmonic dihedral | U = (P2/2)(phi - P1)^2 | 2: (phi_e, k) | none |
| `NCO`  | Normal-cosine dihedral | U = P1*[1 + cos(P2*phi - P3)] | 3: (V_D, m, delta) | P2, P3 |
| `COS`  | Cosine dihedral        | U = P2*[1 + cos(P3*phi - P1)] | 3 | P3 |

**Note**: the *order of parameters as stored* by `afmtogmx`'s parser is
`(V_D, m, delta)` for `NCO` even though the manual presents the formula with
the offset `P3 = delta` last. The report exporter (`src/afmtogmx/core/report.py`)
remaps to PDF order `(delta, V_D, m)` when displaying — see the `'remap'` lambda
on the NCO schema.

### 4.5 [CDIHedrals] — coupled (5-atom) dihedrals (Table 5). First four atoms
define phi, last four atoms define psi (atoms 2..5 are shared).

| Symbol | Meaning | Functional form | # params | Nonlinear |
|--------|---------|-----------------|----------|-----------|
| `CNCO` | Coupled Normal Cosine | U = P1*[1 + cos(P2*phi + P3*psi - P4)] | 4 | P2, P3, P4 |
| `CCOS` | Coupled Cosine        | U = P2*[1 + cos(P3*phi + P4*psi - P1)] | 4 | P3, P4 |

> **Naming note inside `afmtogmx`**: `CDI` is the natural short-form
> abbreviation of "Coupled DIhedral"; `CDIH` is the .off file keyword from
> the manual. They refer to the **same** thing — these are not separate
> categories. Inside the package the two spellings appear in different
> places: `functions.py:761` parses the section named `"CDIH"`, while
> `gen_empty_bonded()` at `functions.py:229` preallocates the dict under
> `molname["CDI"]`, and downstream consumers (`topology.py`,
> `populate_bonded.py`) all read `'CDI'`. When writing code that touches
> coupled dihedrals, accept either spelling and standardize to one internally
> (recommendation: pick `CDI` for in-package keys to match the existing
> majority of consumers).

### 4.6 [CPA] — customized pair interactions (intra) (Table 6 for CPA on p. 19)

| Symbol | Meaning | Functional form | # params | Nonlinear |
|--------|---------|-----------------|----------|-----------|
| `IGP`  | Intramolecular Gaussian damped Power law | U = P1 * r^P2 * exp(-P3*r^2) | 3 | P2, P3 |
| `IEX`  | Intramolecular Exponential | U = P1 * exp(-P2 * r) | 2 | P2 |

### 4.7 [EXClusions] — pairs to exclude from intramolecular nonbonded eval

```
[EXClusions] N
  int_atom1  int_atom2 [int_atom3 ... up to 10]
```

Up to 10 partner atoms per row; pairs `(int_atom1, int_atomX)` are excluded.
Note: atoms beyond `int_atom1` are not pairwise-excluded with each other.

### 4.8 [FUDge] — scale intramolecular nonbonded

```
[FUDge] N fudge_vdw fudge_Cou
  int_atom1  int_atom2
```

Scaling factors for vdW and Coulomb on listed pairs.

## 5. Intermolecular (nonbonded) cards

### 5.1 [COUlomb] / [THC] — Coulombic

| Symbol | Meaning | # params | Nonlinear |
|--------|---------|----------|-----------|
| `COU`  | Coulomb's law (q1*q2 / (4*pi*eps0*r)) | 1: q_prod | none |
| `THC`  | Thole-damped Coulomb | 2: (q_prod, alpha) | alpha |

**Important**: CRYOFF fits **charge products** (`q_prod = q1 * q2`), not individual
charges. Individual charges must be solved separately (see manual §IV.5
"Charge Constraints" and the `CMD` decomposition keyword).

`COU` and `THC` are mutually exclusive for the same atom pair.

### 5.2 vdW types — Table 6 (manual page 23)

The vdW card name is the interaction symbol. The functional forms here are the
authoritative ones from the manual — any conflict with `afmtogmx` docstrings
should be reconciled against this table.

| Symbol | Meaning | Functional form | # params | Nonlinear |
|--------|---------|-----------------|----------|-----------|
| `GLJ`  | Generalized Lennard-Jones | U = P1/r^P3 + P2/r^P4 | 4 | P3, P4 |
| `BUC`  | Buckingham                | U = P1*exp(-P3*r) + P2/r^6 | 3 | P3 |
| `DBU`  | Diffuse Buckingham        | U = P1*exp(-P3*r) + P2*f(r),  f = 1/(1 + exp(-P4*(r-P5))) | 5 | P3, P4, P5 |
| `STR`  | **Shift-truncated** power | U(r) = P1 * [(1/r^P2 - 1/R0^P2) + P2*(r - R0)/R0^(P2+1)]  for r <= R0; 0 otherwise. (R0 = P3.) | 3 | P2, P3 |
| `EXP`  | Exponential               | U = P1 * exp(-P2 * r) | 2 | P2 |
| `GEX`  | Generalized exponential   | U(r) = (1 + P2 + P3*r^2)^-P4 *  similar — see manual | 4 | P2, P3, P4 |
| `POW`  | Power law                 | U = P1 * r^P2 | 2 | P2 (typically frozen to integer like -6, -8) |
| `CSP`  | Cosine-switched power     | U = (1/2)*P1*r^P2 * [cos(pi*(r-P3)/(P4-P3)) + 1] for P3 < r < P4; 0 for r >= P4 | 4 | P2, P3, P4 |
| `GDP`  | Gaussian damped Power law | U = P1 * r^P2 * exp(-P3*r^2) | 3 | P2, P3 |
| `PEX`  | Power-exponential         | U = P1 * r^P2 * exp(-P3*r) | 3 | P2, P3 |
| `DPO`  | Damped power (diffuse)    | U = P1 * r^P2 * f(r),  f = 1/(1 + exp(-P3*(r-P4))) | 4 | P3, P4 |
| `SRD`  | Short-range damped dispersion | U = P1 / (\|r\|^\|P2\| + \|P3\|^\|P2\|) | 3: (C, n, R0) | P2, P3 |
| `TTP`  | Tang-Toennies             | U = P1 * r^P2 * [1 - exp(-P3*r) * sum_{k=0..\|P2\|}((P3*r)^k / k!)] | 3 | P2, P3 |

**Suffixes** (manual p. 23, Table 6 footnote — verbatim):

> "The CRYOFF symbols are the minimal symbols to be used in the .ff file to
> denote their functional forms; **Additional letters could follow the minimal
> symbol for identification such as EXPinter.** Strike-out functional forms
> are obsolete and will not be supported in later versions of CRYOFF."

The **first 3 characters** of a stored interaction-type key name the functional
form. Any trailing characters are a user-chosen identifier — the person who
wrote the .ff file picked them to tell their fits apart (e.g. "the intermolecular
EXP fit" vs "the intramolecular EXP fit"; "the water-water EXP fit", etc.).

Verified suffix-decorated names that appear in this repo's sample .off files
(every one folds back to a Table-6 symbol by `key[:3]`):

| Stored key | 3-char prefix | Source .off file |
|------------|---------------|------------------|
| `EXPW`     | `EXP`         | `test/sample_off_files/h_butanol_fitwater.off`, `test/openmm/FF_input/intra.off` |
| `EXPINTER` | `EXP`         | `test/sample_off_files/butanediol_intra.off`, `test/sample_off_files/big_alanine.off` |
| `EXPINTRA` | `EXP`         | `test/sample_off_files/butanediol_intra.off` |
| `STRC`     | `STR`         | `test/sample_off_files/butanediol_intra.off`, `test/sample_off_files/h_butanol_fitwater.off`, `test/openmm/FF_input/intra.off` |
| `STRCINTER`| `STR`         | `test/sample_off_files/big_alanine.off` |

**Downstream code should match on the 3-char prefix to find the functional
form.** The full stored key is preserved as the user's identifier; it's not
a different physics. The `write_report` exporter in
`src/afmtogmx/core/report.py` follows this — all `EXP*`-prefixed rows render
together under `EXP interactions:` etc.

**Obsolete forms**: the manual lists some functional forms as struck-out and
unsupported in later versions. Without re-checking each one in the source code,
treat anything you encounter outside the table above as suspect.

## 6. Naming gotchas specific to `afmtogmx` (read this if you're editing
   `report.py`, `tabulated_potentials.py`, or topology generation)

These notes capture mismatches between manual-level naming and the package's
internal storage that have caused confusion in past sessions:

1. **`STR` vs `STRC` vs `SHTR`**:
   - `STR` means "shift-truncated" (manual Table 6, p. 23). **Not** "stretched".
   - `STRC`, `STRCINTER`, etc. are suffix-decorated forms of `STR` — see §5.2.
     The "C" / "CINTER" portion is just an identifier picked by whoever wrote
     the .ff file. The functional form is `STR`. The parser preserves the
     suffix as the dict key (e.g. `off.nonbonded[pair]['STRC']`); downstream
     code should look up the functional form by `key[:3]`.
   - `SHTR` is the *Python function name* in `functions.py:78` that computes
     the STR potential. It is not a separate interaction.

2. **`POW` vs `POW_6` / `PEX` vs `PEX_6` / `DPO` vs `DPO_6` / `SRD` vs `SRD_6`**:
   - `POW`, `PEX`, `DPO`, `SRD` are the .off keywords (and what `off.nonbonded`
     uses as dict keys).
   - `POW_6` and the other `_N` variants are *not* stored as keys anywhere.
     They are dispatch-name strings fabricated by
     `tabulated_potentials.py:58,82` once the integer exponent (e.g. `P2 = -6`)
     is resolved from the fit, so the tabulated-potential generator can
     special-case the GROMACS dispersion column.
   - For user-facing documentation: collapse `POW` and `POW_6` (same physics).
     For code that operates on `off.nonbonded` keys: only `POW` exists.

3. **`CDI` vs `CDIH`**: see §4.5. Same category — `CDI` is the short form
   of "Coupled DIhedral", `CDIH` is the .off keyword. **Fixed as of the
   `off-report-export` branch**: `_parse_bonded` in `functions.py` now
   normalizes `CDIH` → `CDI` at storage time so all downstream code sees
   a single canonical key. Earlier in this branch the dict had both an empty
   `CDI` (preallocated by `gen_empty_bonded`) and a populated `CDIH` (from
   the parser), causing combined dihedrals to silently disappear on the
   GROMACS-output path.

4. **Atom-number to name resolution**: `off.bonded[mol]['ATO']['All'][atnum]`
   holds `(vdw_type, coulomb_type)`. The Coulomb type (second element) is the
   name that matches `off.charges[mol]` keys and is what should be printed in
   reports.

5. **NETF / TORQ pseudo-atoms**: every molecule definition's `[atoms]` block
   ends with two pseudo-atom lines named `NETF` and `TORQ` for fitting molecular
   net force and torque. These are not real atoms and must be filtered out of
   bonded/nonbonded loops. `afmtogmx.core.functions._remove_netf_torq_*` does
   this; new code should call those helpers (or replicate their filter).

6. **Default attractive set**: `tabulated_potentials.py:155` lists
   `['POW_6', 'DPO_6', 'SRD_6']` as the default attractive interactions placed
   in columns 4-5 of GROMACS tabulated potentials. `PEX_6` is listed as
   "supported" in some docstrings (`tabulated_potentials.py:162`) but the
   actual implementation at `tabulated_potentials.py:287-288` prints
   "CANNOT HANDLE PEX AT THE MOMENT" — so PEX is currently a known gap.

## 7. The .off output structure (what `afmtogmx` parses)

The `.off` file has five sections in this fixed order:

1. **Atom Types** — the header lines.
2. **Intra-Potential** — fitted bonded parameters per molecule, in CRYOFF
   native units (kcal/mol, Å, deg). This is what `[BONds]/[ANGles]/[BD3]/
   [DIHedrals]/[CDIHedrals]` produce.
3. **Inter-Potential** — fitted nonbonded parameters per atom pair. Each
   line ends with `Min: ... Max: ...` giving the distance range over which
   the parameter was fit. Distances between solvation-factor-0 atoms are not
   counted in MIN/MAX.
4. **Molecular-Definition** — same parameters as Intra-Potential, but
   restated in GROMACS-friendly order with unit conversion (kJ/mol, nm).
5. **Table-Potential** — Coulombic + short-range non-bonded per atom pair,
   formatted for the AFM toolkit's table-file generator.

Only sections 1, 2, 3 carry physics that isn't re-derivable from the others;
the rest are presentation. `afmtogmx` parses section 2 → `off.bonded` and
section 3 → `off.nonbonded`.
